# Select_Server

Windows Winsock의 `select`를 기반으로 구현한 **C++ TCP 채팅·오목 서버**입니다.
다중 클라이언트의 연결과 패킷 송수신을 처리하고, 유저·방 관리부터 2인 오목 대전까지 구성했습니다.

TCP 스트림의 특성을 고려한 패킷 처리, 네트워크와 게임 로직의 책임 분리, 서버에서의 게임 상태 검증에 중점을 둔 포트폴리오 프로젝트입니다.

## 기술 스택

| 구분 | 사용 기술 |
| --- | --- |
| 언어 | C++20 |
| 네트워크 | Winsock2, TCP, 논블로킹 소켓, select |
| 개발 환경 | Windows, Visual Studio 2022, MSVC v143 |
| 테스트 | FakeNetwork 기반 서버 로직 테스트 |

## 주요 기능

- **로그인·채팅:** 닉네임 로그인, 중복 닉네임 검사, 채팅 메시지 전송
- **방 관리:** 방 생성·목록 조회·입장·퇴장, 방장과 준비 상태 관리
- **오목 대전:** 15×15 보드, 2인 대전, 착수 위치·차례 검증, 승리 판정 및 기권
- **제한 시간:** 로그인 타임아웃과 턴마다 5분의 착수 제한 시간 적용
- **연결 종료 처리:** 유저·방 상태 정리 및 진행 중인 게임 종료
- **콘솔 클라이언트:** 서버 IPv4 입력, 명령 기반 조작과 오목판 출력

## 핵심 설계 및 구현

### TCP 패킷 조립과 부분 송신

TCP 수신 데이터가 애플리케이션의 패킷 단위와 일치하지 않는 점을 고려했습니다. 패킷 길이와 ID로 구성된 4바이트 헤더를 사용하고, 클라이언트별 수신 버퍼에 데이터를 누적해 완성된 패킷만 처리합니다. 하나의 패킷이 나뉘어 도착하거나 여러 패킷이 한 번에 도착하는 경우를 처리합니다.

송신 시에는 실제 전송된 바이트만 버퍼에서 제거합니다. 남은 데이터는 이후 소켓이 쓰기 가능한 시점에 다시 전송하며, 접속 수·송수신 버퍼·이벤트 큐 크기에 상한을 두었습니다.

### 네트워크와 게임 로직 분리

`SeverNetLib`는 소켓과 세션, 송수신 버퍼를 관리하고 연결·패킷·연결 종료 이벤트를 전달합니다. `LogicLib`는 `INetwork` 인터페이스를 통해 이벤트를 처리하고 응답을 전송합니다.

게임 로직이 구체적인 소켓 구현에 직접 의존하지 않도록 구성해, 테스트에서는 실제 네트워크 대신 `FakeNetwork`를 사용할 수 있게 했습니다.

### 서버 중심의 상태 검증

클라이언트 요청을 처리할 때 로그인 여부, 소속 방, 방장 권한, 준비 상태와 게임 진행 상태를 확인합니다. 착수 요청에는 방·게임 ID, 차례, 좌표와 빈칸 여부를 검증하여 잘못된 요청이나 이전 게임의 요청이 현재 게임에 적용되지 않도록 했습니다.

정상 착수 후에는 다음 턴의 제한 시간을 갱신하고, 타임아웃이나 연결 종료 시 게임 결과와 관련 상태를 정리합니다.

## 프로젝트 구조

| 프로젝트·폴더 | 역할 |
| --- | --- |
| ChatClient | 콘솔 입력, 서버 접속, 응답 처리 및 보드 출력 |
| ConsoleHost | 서버 초기화, 실행 루프와 종료 처리 |
| SeverNetLib | select 기반 TCP I/O, 세션·버퍼·네트워크 이벤트 관리 |
| LogicLib | 패킷 처리, 유저·방 관리 및 오목 게임 로직 |
| Common | 서버·클라이언트 공통 패킷 정의와 인코딩·디코딩 |
| ServerTests | FakeNetwork를 사용하는 서버 로직 테스트 |

## 테스트

다음 상황을 검사하는 테스트를 구성했습니다.

- 로그인 성공·실패, 중복 닉네임 정리, 로그인 전 요청과 로그인 타임아웃
- 채팅 브로드캐스트와 지원하지 않는 패킷 ID 처리
- 방 생성·입퇴장, 준비 상태와 게임 시작 조건
- 착수 검증, 방향별 승리 판정 및 게임 초기화
- 턴 타임아웃, 이전 게임 요청 거부, 연결 종료 시 게임 종료

테스트는 실제 소켓 연결 없이 로직을 검증하며, 인터넷 접속이나 부하 성능 검증은 포함하지 않습니다.

## 실행 환경 및 범위

Visual Studio 2022에서 `SelectChatServer.sln`을 열어 `x64`로 빌드합니다. 서버인 `ConsoleHost`를 먼저 실행하고 `ChatClient` 두 개로 대전을 확인할 수 있습니다. 로직 테스트는 `ServerTests`로 실행합니다.

닉네임 기반 콘솔 프로젝트이며, 계정 인증·암호화·DB 영속 저장은 현재 구현 범위에 포함하지 않습니다.

## 간단한 배포 방법

- `Release | x64`로 빌드한 뒤, 서버 PC에서 `ConsoleHost.exe`를 실행하고 접속할 사용자에게 `ChatClient.exe`와 필요한 런타임을 전달합니다.
- 클라이언트 실행 시 서버 IPv4를 입력합니다. 같은 PC에서는 Enter만 누르면 `127.0.0.1`로 접속합니다.
- 다른 PC의 접속에는 서버 방화벽의 **TCP 32452** 허용이 필요하며, 다른 네트워크에서는 공인 IPv4와 공유기 포트 전달 설정도 필요합니다. 실제 외부 접속은 별도 검증이 필요합니다.
